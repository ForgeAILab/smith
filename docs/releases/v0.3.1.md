# Smith v0.3.1

Smith 0.3.1 redraws the terminal UI on Claude Code's grammar: one row per
tool call with its result nested beneath, progress above the composer, one
Markdown renderer, approvals that lead with the action, and aligned
informational results. Provider requests, approval policy, and configuration
are unchanged.

## Transcript

- Each tool call is one row, `● Bash(ls -la)`, with its reviewed label and
  argument. Results nest under `⎿`: four lines, then
  `… +N lines (ctrl+o to expand)`. Tools without a useful preview get a
  one-line summary such as `Read 6 lines`. A denied call reads `denied` with
  a short reason. A turn that changed no files gets no changes notice.
- `Ctrl+O` expands and folds tool output, approval detail, and diffs.
- A `!command` you type echoes once as `! command` with its output nested.
  It is now saved with the session, so a resumed session shows it in place.
  The command and a bounded, redacted copy of its output go to an owner-only
  `<session-id>.shell.jsonl` beside the session snapshot. They never enter
  the event journal or the history the model sees.
- Assistant text renders through one Markdown renderer while it streams and
  after it commits: headings, emphasis, inline and fenced code (with a dim
  language label instead of fence lines), nested lists, quotes, tables, and
  links that show their URL.

## Progress and approvals

- The working row sits above the composer:
  `✻ Working… (12s · ↓ 1.2k tokens · esc to interrupt)`. A successful turn
  ends with a dim `✻ Worked for …` that disappears when anything else is
  added.
- An approval opens with what will run, then where and for how long, the
  warning, the question, and `y` / `a` / `n`. The identity hash, permissions,
  and raw arguments move behind `Ctrl+O`. The transcript stays scrollable
  while a prompt is open.

## Commands and results

- The command menu, palette, and resource pickers use aligned name and
  description columns; argument grammar, provenance, and limits appear only
  for the selected row.
- `/help`, `/status`, `/context`, and `/diagnostics` use aligned label and
  value columns that wrap at words. A result taller than the pane opens at
  its first line. `/help` leads with a short "Start here" and lists keys in
  plain words.
- `/diagnostics` groups its facts under Session, Context, Cache, and
  Recovery, one per line, with detail facts nested under their parent.
  Values appear exactly as stored, and anything unreported reads `unknown`.
  The footer reads `unknown ctx` before the first plan.
- A child agent's state reads the same everywhere: `running`, `idle`,
  `interrupted (resumable)`, `stopped (by request)`, and so on, with
  `durable` or `ephemeral`. Headless machine output is unchanged.

## Composer

- The composer sits between two rules with a `>` prompt. A leading `!`
  switches it to bash mode; Backspace on the bare `!` leaves it.
- Up and Down move between the lines of a draft and reach history only from
  the first or last line. `\` then Enter inserts a newline. `Ctrl+A`/`E`,
  `Ctrl+W`, `Ctrl+U`, `Ctrl+K`, and `Alt+B`/`F` edit the draft.
- `? for shortcuts` on an empty draft opens a shortcuts panel; any key
  closes it.
- First-run setup draws one frame with wrapped descriptions, and its footer
  keys stay visible at 44x16.

Existing profiles, configuration, and sessions remain compatible.
