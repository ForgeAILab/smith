# Smith v0.4.0

Smith 0.4.0 adds file commands, installable plugins, a module system with
sandboxed WASM modules, and agent-driven capability discovery. It also makes
the trust file readable by older and newer Smith builds alike, and picks up
security fixes in rustls and Wasmtime.

## Changed

- **Core tools are always active.** `read`, `list`, `search`, `edit`,
  `shell`, `task_output`, and `task_stop` are in the tool list from the first
  request, narrowed only by the profile's posture and capability limits. They
  no longer have to be found by search first. This reverses the earlier rule
  that `edit` and `shell` were not offered merely because they were
  installed, and it removes the `shell` keywords added in 0.3.10. In a
  headless run, a model may now call `shell` where it previously could
  not; if the approval policy needs someone to approve that call, it is
  refused and the result status is `approval_required`.
- **Image generation and the budget notice are modules.** Each can be
  switched with `[modules.<id>] enabled` or `/modules <id> on|off`. Their
  existing configuration keys keep working as aliases.
- **For embedders only:** `Contribution` and `ModuleProvenance` in
  `smith-runtime` gain variants, and a host that builds a `RuntimeRequest`
  directly gets image generation and the budget notice only if it passes them
  in `RuntimeRequest.modules`.

## New

- **The agent can browse and activate capabilities.** `registry.search`
  accepts an empty query and an optional domain and lists the authorized
  catalog page by page; a search with no match reports how many capabilities
  each domain holds. `registry.activate` stages capabilities by id for the
  next request. Search now matches names, summaries, and descriptions, not
  only keyword lists.
- **Capability limits.** A profile can declare `capabilities.allow` and
  `capabilities.deny` patterns over registry ids. A denied capability is
  absent from the session: not active, not listed, not searchable.
  `/capabilities` shows what is active, what can be activated, and what is
  denied; `/capabilities deny <id>` narrows the session further.
- **File commands.** A markdown file at `commands/<name>.md` under
  `~/.smith/` or a project's `.smith/` becomes `/name`. The body is a prompt
  template: `$ARGUMENTS` is replaced by the text after the command, and
  frontmatter may set `description` and `argument-hint`. File commands appear
  in completion, `Ctrl+P`, and `/help`, and work headless as
  `smith -p "/name args"`. Built-in names cannot be shadowed. A project's
  commands run only after `/commands trust <name>`, bound to the file's
  content. `/commands` lists them and `/commands reload` rereads them.
- **Plugins.** `smith plugin add <source>` installs a plugin from a local
  directory, `github:owner/repo[#ref]`, a git URL, or a marketplace
  registered with `smith plugin marketplace add`. Plugins use the Claude Code
  layout, so an existing Claude Code plugin installs unchanged. Skills,
  commands, and MCP servers are loaded; other components are listed with the
  reason they are not loaded yet. Installing shows everything the plugin
  would load and asks for confirmation, bound to a digest of every file; an
  update that changes content asks again. `/plugins` and `smith plugin
  list|update|remove` manage them, and `/plugins <name> on|off` switches one.
- **Modules.** `/modules` and `smith config modules` list every module,
  whether it is compiled in and mounted, and where that choice came from. A
  change applies at the next idle turn.
- **Sandboxed WASM modules.** A plugin can ship a WASM component that adds
  tools, context, tool-output processing, and status items through the
  versioned `smith:module` interface. A module has no filesystem, network,
  environment, or clock access beyond what its manifest requests and the
  install confirmation granted. Every call is bounded in time, memory, and
  payload size; repeated failures disable the module for the session without
  ending it. The `smith-module-sdk` crate and `examples/wasm-module-hello`
  show how to write one.

## Fixed

- **An older Smith no longer refuses a newer Smith's trust file.** All Smith
  builds on a machine share `~/.smith/trust.json`. A decision of a kind an
  older build did not know, such as a project file command, made the whole
  file unreadable, and that build refused to start in every project. Smith
  now ignores a decision it does not understand, keeps it in the file when it
  saves, and lets it authorize nothing. 0.3.10 and earlier still fail on such
  a file; this works from 0.4.0 onward.

## Security

- **rustls 0.23.46** fixes RUSTSEC-2026-0346, -0347, -0348, and -0349.
- **Wasmtime 36.0.18** fixes RUSTSEC-2026-0363.

Agent Runtime moves to `d2752c1` for capability browsing and activation;
0.3.10 used `fc92efb`.
