# Smith v0.3.4

Smith 0.3.4 makes confirmations and notices consistent, and shows budget
failures that were silently dropped.

## Confirmations

Every confirmation — undo, redo, revert, MCP and skill trust, review, child
invocation, follow-up and resume, account switch, and quit — now uses one
box: a title, an optional warning, a body, `y` to accept, and `n` or Esc to
cancel. Enter chooses neither. The body scrolls with the arrow and page keys,
so a long undo, redo, or revert patch can be read to its last line; before,
it was cut off.

Prompts that need an answer are never replaced by another: approvals,
questionnaires, and confirmations queue in the order they arrive. A picker
closes when a prompt arrives and cannot open over one.

## Notices

A reply to your own keypress that changes nothing — a command refused while
a turn runs, an already-current selection, an empty clipboard — now shows in
the hint row until your next key instead of adding a line to the
transcript. Everything else Smith, a provider, a child, or a monitor reports
stays in the transcript as before.

## Fixes

- A context or output budget that cannot be met is now reported in the
  transcript with the requested and allowed token counts, and appears as a
  typed `budget_failure` event in headless stream output. Before, Smith
  dropped it.
- Headless stream output also carries provider rate-limit observations as
  typed `rate_limit_observation` events.

## For developers

The unused command half of Smith's client protocol (`SmithInput`, turn and
steer receipts, `SmithSession::submit/steer/cancel`) is removed; hosts drive
sessions through the runtime session handle, and `SmithEvent` remains the
client-facing projection. A build now fails when the pinned runtime adds an
event Smith does not mirror. Modules of `smith-runtime` that nothing outside
the crate uses are private.

Existing profiles, configuration, and sessions remain compatible.
