# Smith v0.7.0

Smith 0.7.0 moves Agent Runtime to v0.5.0 and gives WASM modules interface
0.2: modules can call the session's model and wake an idle session. An
installed coding agent can now serve as the advisor, skills load from
`.agents/skills`, and the composer accepts line breaks in every terminal.

## Upgrade notes

- **Session formats are unchanged.** Sessions written by 0.6.0 resume in
  0.7.0. Runtime events in stream-json stay at event schema 16, and the
  result envelope stays at schema 3.
- **For headless consumers:** stream-json can carry a new line type,
  `module_notification`, when a WASM watcher delivers a notice. The usage
  output gains an optional `modules` map, keyed by module, when a module
  called the model. Both are additive.
- **WASM modules:** Smith keeps loading interface 0.1 modules unchanged. A
  module's id is now readable, `<plugin>/<component path>`. The old hashed
  id stays an alias, so install records, grants and configuration that name
  it keep working without a reinstall.

## New

- **WASM interface `smith:module@0.2.0`.** See `docs/wasm-modules.md`.
  - `complete` sends one bounded, non-streaming, tool-free model request on
    the session's current route (provider/model or installed agent). It
    needs the new `model` capability, confirmed at install. Output tokens
    per call and calls per turn are capped, and you can narrow both. Usage
    is recorded under the module's name and counts toward session totals.
  - A `watcher` contribution with a `poll` export. Smith polls each watcher
    while the session is live and delivers its notices through the session
    inbox: an idle session takes a turn, and a busy one receives them at
    the next safe boundary. It needs the new `session_notify` capability.
  - The `relay` example now delivers messages with a watcher, and a new
    `second-opinion` example uses `complete` with `session_history`.
- **An installed coding agent can be the advisor.** Use
  `advisor = "cli/claude-code/opus"` in configuration, in the session
  override, or from `/advisor`. Each call runs one fresh, read-only CLI turn
  with the CLI's own tools off. `/advisor` lists the same rows as `/model`.
  A row the advisor cannot use is shown disabled with the reason. A vision
  target cannot be an installed agent.
- **Skills under `.agents/skills`.** Smith also reads
  `~/.agents/skills/<name>/SKILL.md` and `<project>/.agents/skills/…`, the
  latter under the same project trust as `.smith/skills`. Within a layer,
  `.smith/skills` wins, and `/skills` reports the shadowed skill.
  - Frontmatter `description` may be a YAML block scalar (`>` or `|`) or a
    quoted value.
  - A frontmatter `name` that differs from the directory is ignored instead
    of refused. A skill is named by its directory.
- **Choose a context window from `/context`.** When the active model has
  more than one named window and the session is idle, `/context` also opens
  a picker above the composer. `/context NAME` is unchanged.
- **Line breaks in every terminal.** Ctrl+J inserts a newline everywhere.
  Shift+Enter, Alt+Enter and `\` then Enter still work. Where the terminal
  supports the kitty keyboard protocol, Smith enables escape-code
  disambiguation while it owns the screen and restores the terminal on every
  exit path. Tall drafts scroll to keep the cursor visible.
- **Trusted ChatGPT models get reasoning controls by default.** They have
  efforts `low` through `ultra` and default to `medium`, without the block
  `/connect chatgpt` writes. An explicit `[models."chatgpt/<model>".reasoning]`
  block still wins.

## Changed

- **Agent Runtime moves to v0.5.0** (`82f5aac`, tag `v0.5.0` on runtime
  `main`). 0.6.0 used v0.4.0 (`1d0a821`). The advisor, the summary and vision
  now share the runtime's one-shot call. Error text, usage attribution,
  limits and cancellation are unchanged.
- **Images are fitted to the provider on every request.** Images were
  prepared once, when they entered the conversation. Now each request
  re-fits any image that exceeds the serving provider's limits, from every
  source: `read`, `@FILE`, `--image`, pasted images, MCP results and
  generated images. Results are cached, so a repeated image is prepared once
  per provider. An image that cannot be prepared becomes
  `[image omitted: <reason>]` instead of failing the turn. History keeps the
  image as ingested.
- **Setup uses the `/model` picker.** Setup's default-model step uses the
  same compact picker and rows as `/model`, including installed agents with
  their PATH check. Every pre-session screen now sits at the bottom of the
  terminal: setup, the ChatGPT and xAI login screens, the connection review,
  and `smith --resume`. The model, provider, profile, thinking, effort and
  advisor pickers open on the current choice.
- **Models that define only named windows** now appear and are marked
  current in `/model`, setup and `/provider` counts.

## Fixed

- **MCP server output no longer reaches the terminal.** Each stdio server's
  stderr is captured, redacted and written to the session log. When a
  server fails to start or exits, its last lines are attached to the failure
  that `/mcp` and the status bar show. A server that exits after connecting
  is now reported as failed instead of staying `connected`. Headless runs
  add one diagnostic per server that failed to start.
- The MCP footer keeps its failed count across a session rebind.
- A WASM context contributor without the session-history capability runs
  with an empty history instead of being refused. A view that cannot fit the
  payload limits skips that call and no longer counts toward disabling the
  module.
