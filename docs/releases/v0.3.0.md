# Smith v0.3.0

Smith 0.3.0 adds an advisor: the working model can consult a stronger model
at the moments that decide a task, without starting a child agent.

## Advisor

Set `advisor` to a profile or a model, the same way you pick one elsewhere:

```toml
advisor = "sol"                    # a configured profile
# advisor = "chatgpt/gpt-6.1-sol"  # or a provider/model
```

With an advisor configured, root sessions offer a model-facing `advisor` tool
that takes no arguments. Calling it sends the conversation so far, including
this turn's tool calls and results, to the advisor as one tool-free request,
and returns its advice as the tool result. The main model is told to consult
it before substantive work, when stuck, and before declaring a task done.

- A profile advisor uses that profile's provider, model, reasoning, limits,
  and instructions. A model advisor uses only top-level settings and its
  `[models."<provider>/<model>"]` entry; the main profile's settings do not
  reach it.
- A profile's own `advisor` key overrides the top-level default, and
  `advisor = false` turns it off. Nothing advises itself: running `sol` as the
  main profile with `advisor = "sol"` simply has no advisor.
- `/status` shows advisor usage on its own line and includes it in the
  session cost when the advisor's model has a catalog price.
- Child agents never get the tool.

The advisor receives the whole conversation, including tool output and file
contents, and may use a different provider from the main model. The feature
is off unless `advisor` is set.

## Other changes

- A retrying provider call shows its attempt and wait in the turn instead of
  appearing stalled.
- Approval, trust, rotation, and recovery prompts ignore keys typed within
  500 ms of appearing, so text you were already typing cannot answer them.
- Guided setup's Anthropic Messages and ChatGPT entries now start their
  flows. Cancelling a picker opened by a command leaves the composer empty,
  and the redo, MCP-trust, and skill-trust dialogs describe their own action.
- A `!command` you type runs without an approval prompt; model-requested shell
  calls still follow the approval policy.
- `smith help` and `--help` work on every subcommand, a parse error prints one
  hint, an interactive launch without a terminal explains itself, the
  configured `background.exit_policy` applies to headless runs, and
  `smith sessions list` prints aligned columns on a terminal.
- Internally, session accounting and the slash-command table moved into a new
  `smith-client` crate, and every local command returns typed data. Command
  output is unchanged.

Existing profiles and configuration remain compatible.
