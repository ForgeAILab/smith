# Smith v0.3.8

Smith 0.3.8 stops a sub-agent's result from being answered twice.

## Fixes

- **A sub-agent's result is answered once.** When the main agent spawned a
  sub-agent, waited for it, and answered from its result, Smith then
  delivered the same result again in a turn of its own, and the model
  answered a second time. Every task that waited for a sub-agent paid for an
  extra model call. A result the model has already read through `wait` or
  `result` is no longer delivered again. A sub-agent the model does not wait
  for is still delivered automatically when it finishes. Checked live on
  `zai/glm-5.3`: the same prompt took two turns and answered `pong` twice on
  0.3.7, and takes one turn with one answer on 0.3.8.
- **Headless runs end when that result was read.** `smith -p` waited for the
  automatic delivery after any sub-agent finished. It now ends after the
  turn when the model has already read the result, and still waits when a
  delivery is coming.

## Under the hood

- Agent Runtime moves to `fc92efb` (`fix/smith-agent-result-delivery`): a
  host delegation tool can acknowledge the outcome it returns, and the
  runtime withdraws it from automatic delivery once that tool result is saved.
  If the process stops in between, the result is delivered again rather than
  lost.
- A host-restart delegation test no longer shuts down while the automatic
  delivery turn is in flight; it failed only under heavy load.
