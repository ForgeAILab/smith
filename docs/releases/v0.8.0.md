# Smith v0.8.0

Smith 0.8.0 adds ordered model fallback to profiles, reports child tasks that
stop at a limit, replaces blocking agent waits with wake timers, and prices
images per provider when planning requests.

## Changes

- Profiles can list fallback models under `[profiles.<name>.fallback]`, with
  an optional `first_response_timeout_ms`. When the primary fails before any
  output, or misses the deadline, the turn moves to the next model; the next
  user turn starts on the primary again. Child routes inherit the chain, and
  a fallback on another pooled provider starts on that provider's remembered
  account. See [Model fallback](../guides/profiles-and-advisor.md#model-fallback).
- A child task that ends at a configured limit is reported as
  `stopped_at_limit` with the limit kind, not as a completed task carrying an
  earlier message. The child stays idle and accepts follow-ups; the TUI row
  names the limit.
- `agent wait` returns immediately and arms a single-use wake timer. The
  parent wakes when the child finishes or the deadline expires; a timer that
  expires during a parent turn is delivered when that turn ends. The TUI
  shows `monitor` with the wake time, and a zero-timeout wait reports an
  armed timer.
- `agent wait`, `agent list`, and the wait-timeout turn include an `activity`
  object for running children: elapsed time, committed steps, the last step,
  pending tools, and the size of a response still streaming. Streaming
  content is never quoted.
- `artifact.list` returns the session's own artifacts, newest first, with the
  child that produced each copy. A not-found error names `artifact.list`
  instead of inviting constructed IDs.
- Request planning prices each inline image at its provider's published
  rate: Anthropic and OpenAI patch or tile rules per model, Gemini tiles for
  1.x/2.x and a flat 1,120 tokens for Gemini 3 and 4, and the OpenAI patch
  rule for xAI and compatible adapters.
- `/compact` names why it could not run (a turn running, Runtime busy, a
  request pending, missed events), and an explicit request can retry within
  the same idle interval. History the current summary already covers is
  reported as nothing to compact, not as a failure.
- Invoking a skill (`/name [task]`) submits a turn whose prompt is the
  skill's instructions followed by the task text.
- Sessions get a developer fragment naming the tools they may activate.
  Provider tool names drop hash suffixes (`registry.search` is sent as
  `registry_search`), and tools sharing a provider name are skipped instead
  of failing the session.
- ChatGPT native requests stay on the session's prompt cache: `session-id`
  matches the cache key and the turn-state token is replayed during a tool
  loop.
- A binary `@file` is sent as a path reference with its size instead of
  refusing the submission.
- Delegation guidance no longer tells the model to "park", and says that
  child outcomes arrive only as later host messages.
- The locked `tokio` dependency is updated to 1.53.3, addressing
  [RUSTSEC-2026-0386](https://rustsec.org/advisories/RUSTSEC-2026-0386).

## Compatibility

- stream-json runtime events are schema 17 (was 16), which adds
  `ChildLimitReached`; fallbacks are reported as `ModelFallback` events.
  Journals written by 0.7.13 resume in 0.8.0.
- Sessions upgrade one way. An unfinished turn that used fallback is
  checkpointed with transition revision 5, which 0.7.13 refuses to resume.
- Installed `cli/...` agents do not support model fallback. An explicit
  `/model`, `--model`, or `--provider` selection disables the chain until
  the profile is selected again.
- No user credentials or personal configuration are included in the release.
- Agent Runtime is pinned to `046a942146efafb00f787e52f3df03ad90d67b4a`
  (0.7 line; also on Agent Runtime `main` through PR #77).
