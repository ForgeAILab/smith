# Smith v0.1.0

Smith 0.1.0 is the first release with skills, project-declared MCP servers,
local command model providers, and delegation controls. It also fixes a hang
that could leave a headless run alive forever after a child agent finished.

## Skills

A skill is a named, bounded instruction body with a searchable descriptor.
Smith indexes descriptors and materializes a body only when the agent
activates that skill, so an unused skill costs its descriptor rather than its
text. Activation contributes instructions only: a skill can never grant a
tool, permission, approval, credential, executable trust, or a wider
workspace. Declarations resolve built-in, then user
(`~/.smith/skills/<name>/SKILL.md`), then workspace
(`<project>/.smith/skills/<name>/SKILL.md`, gated by project trust), then
session. See [Skills](../skills.md).

## Project-declared MCP servers

A project can declare the MCP servers it needs, and `smith-runtime` carries
the `http` transport alongside the default `stdio` one. Connected MCP tools
reach the model through the same activation, approval, and usage path as the
built-ins.

## Local command model providers

The `command-jsonl` provider kind puts a trusted local bridge behind the same
model boundary as the native HTTP adapters, over a revisioned stdin/JSONL
protocol with bounded process supervision. Smith keeps ownership of canonical
history, context planning, built-in and MCP tool execution, approvals,
retries, cancellation, usage, journals, persistence, and both TUI and headless
presentation.

The process declaration is owner-controlled: an absolute canonicalizable
executable invoked without a shell or `PATH` lookup, fixed non-secret argv, a
`workspace`-or-absolute working directory, and a fully explicit environment.
Project configuration may select a user-declared command provider but cannot
define or override its executable, arguments, working directory, or
environment.

This is a model-level protocol, not an adapter for autonomous coding CLIs.
Codex app-server and similar agents own their own threads, tool execution,
approvals, and persistence; presenting those as a stateless model turn would
create a second owner for state Smith already owns. See
[Local command model providers](../configuration.md#local-command-model-providers).

## Delegation controls and adaptive cache lifecycle

Child agents gained bounded foreground waits, so a parent that delegates no
longer blocks indefinitely on a slow child. Prompt-cache maintenance gained an
explainable `off` / `observe` / `adaptive` policy; `adaptive` dispatches only
for a model that has passed the matching conformance fixture and only when the
host was started with `--allow-synthetic-cache-spend`. Cache-miss notices are
opt-in through `cache.miss_notices`.

## Fixed: headless never exited after a child agent completed

A child outcome that became ready as its parent's turn was ending could be
refused once by the runtime's admission boundary, because that boundary was
still settling. Smith's admission worker was woken only by runtime events, so
a refusal arriving after the last event of a run was never retried: the
outcome stayed ready and undelivered, and `smith -p` waited for required child
work forever instead of printing its answer and exiting.

Transient refusals are now retried on the worker's own bounded schedule,
backing off from 20ms to 500ms so a parent that stays occupied is polled
rather than spun on.

This affected headless runs only; the interactive TUI has its own loop.

## Security

Tool and extension boundaries were hardened, and an invalid `agent` action is
now returned to the model as a tool error it can correct rather than failing
the turn.

## Upgrading

The macOS and Linux archives, the curl installer, and
`@forgeailab/smith@0.1.0` all carry this version. Existing
`~/.smith/config.toml` files, sessions, and protected checkpoints are read
unchanged; no configuration migration is required.
