# Smith v0.7.5

Smith 0.7.5 reports why a provider rejected a request, resumes sessions
whose sub-agent profiles changed, delivers long sub-agent replies reliably,
and adds a live conformance suite.

## Upgrade notes

- **Session formats are unchanged.** Sessions written by 0.7.4 and earlier
  resume in 0.7.5. Runtime events in stream-json stay at event schema 16, and
  the result envelope stays at schema 3.
- **Profile revisions change once.** A profile's revision no longer depends
  on the path of the file it was read from, so every revision is new after
  the upgrade. Finished sub-agents keep their results. A sub-agent that was
  interrupted under an older Smith is listed as changed and cannot resume;
  start it again.
- **Error labels.** A request the provider refused now reads `Provider: ...`
  instead of `Config: ...`. Scripts that matched `Config:` for provider
  rejections need updating.

## Fixes

- **Errors say what the provider said.** A rejected request used to read
  `Config: Gemini provider rejected the request`. It now carries the
  provider's own reason, for example
  `Provider: Gemini provider rejected the request: invalid_request: Request contains an invalid argument.`
  This reason reaches the transcript, headless results, and a sub-agent's
  report to its parent. Gemini answers a streamed request with an SSE
  `error` frame, which Smith now reads. Authentication failures carry it
  too: a gateway that answered 403 because its account was out of credit
  read only `provider authentication rejected`, and now ends with
  `Insufficient quota. Please top up and try again.` A reason that repeats
  any credential Smith sent, including the bare token of a `Bearer` header,
  is dropped whole, and reasons are capped at 300 characters.
- **Sessions resume after a sub-agent profile changes.** Editing a profile
  that a session's sub-agents had used, or no longer marking it as a child
  profile, made the whole session fail to resume with
  `no preflighted agent-profile route`. So did reading the same configuration
  from another path. The session now resumes, and only the affected
  sub-agent is reported as changed.
- **Context planning counts Gemini's saved search steps.** Each replayed
  Google Search step costs about 9,000 input tokens, mostly Gemini's
  signature, and the planner counted it as zero. It now counts signatures,
  so a session that searched often plans against its real size.
- **Long sub-agent replies reach their parent.** A reply over 4,096
  characters used to stop automatic delivery, including later children's
  results. Replies now arrive in full while they fit
  `context.tool_output_inline_bytes` (8 KiB by default); longer replies
  arrive as a 1 KiB excerpt and a reference to a parent-owned copy readable
  with `artifact.read`. Deliveries also name artifacts copied from the child.
- **A completed turn is ready for the next action.** Completion now waits
  for the turn's admission gate to be released, preventing an immediate
  local tool action or idle compaction from being refused as busy.

## Testing

- **Live conformance suite.** `cargo test -p smith-cli --test live_conformance -- --ignored`
  runs real turns against the routes in `SMITH_LIVE_CONFORMANCE_MODELS`: a
  tool turn, a resumed continuation, a turn killed after its first tool
  result and then resumed, hosted search plus a tool, and every ordered pair
  of routes handing a session over. It writes `report.json` and `report.md`
  with each scenario's usage, cache-read percentage and full error text. See
  the README. Before this release it passed every scenario on
  `google/gemini-4-argon`, `chatgpt/gpt-5.6-luna` and `zai/glm-5.3`,
  including every cross-provider handover among them.

## Under the hood

- Agent Runtime moves to v0.7.0 plus the fixes merged on runtime main at
  `70c4f96` (PRs #51, #52, #55, #56 and #58). This pin also includes opt-in
  retirement and collection in the reference in-memory session journal;
  Smith does not enable automatic collection. Session and checkpoint
  formats remain unchanged.
