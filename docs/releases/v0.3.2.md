# Smith v0.3.2

Smith 0.3.2 keeps the screen when you change how a session runs, and fixes
`/agent resume`.

## Changing model, profile, or effort keeps the screen

Picking a model, profile, effort, thinking setting, or context window, and
cycling profiles with Tab, used to leave the screen and start the interface
again: the transcript was rebuilt from history alone, and local results such
as `/status`, notices, scroll position, and composer history were lost. In
0.3.1 a model switch could leave the transcript empty.

Smith now keeps the terminal and the interface for the whole run. A change
that keeps the same session rebuilds what runs the session underneath and
leaves what you see in place: the transcript as shown, folded and expanded
rows, scroll position, the composer, and its history. One notice says what
changed, and the footer and `/status` show the new settings. The same applies
when an MCP server finishes connecting and when you connect or disconnect
another provider; a connection flow that draws its own screen returns you to
the same transcript.

Switching to another session with `/new` or `/resume` shows that session's
history and keeps your composer history. A change requested while a turn is
running is refused, as before, with a notice that it needs an idle turn.

## Fixes

- `/agent resume` works again for an interrupted child with an exact
  checkpoint. In 0.3.1 it reported every interrupted child as incompatible.
- Asking an interrupted child for a follow-up again points to
  `/agent resume <id>`.
- Resuming a session whose saved thinking or effort setting the starting
  model cannot use now clears that setting with a notice and starts, as
  intended. Before, Smith refused to start the session.

Existing profiles, configuration, and sessions remain compatible.
