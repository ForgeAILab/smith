# Smith v0.7.3

Smith 0.7.3 keeps custom OpenAI-compatible providers' model lists current and
discovers model limits before asking you to enter them during setup.

## Upgrade notes

- **Daily model refresh is enabled by default.** Smith checks user-configured
  custom OpenAI-compatible providers on startup when their cache is due and
  every 24 hours while running.
  Use `smith models sync --force` to refresh immediately, or add
  `--provider NAME` to refresh one provider. Configure the interval or disable
  automatic refresh under `[model_sync]`.
- **Existing model selections stay selected.** Discovery adds current provider
  models to `/model`; it does not silently replace an explicitly configured
  model. Restart Smith after upgrading to use the updated picker and setup.
- **Usage records now use schema 6.** Older records remain readable. Historical
  costs without a recorded price remain unknown rather than being recalculated
  with today's price. Session formats, runtime event schema 16 and result
  envelope schema 3 are unchanged.

## Fixes

- **Custom provider models appear without manual catalog maintenance.** Discovery
  uses the provider's user-configured endpoint and credentials, including inline API
  keys. Account-scoped caches retain the last successful result when offline.
- **Setup detects published limits first.** Context, input and output ceilings
  are filled from discovered metadata when available; manual entry remains
  available for missing fields. Published output ceilings remain separate from
  the output budget for a request. Adding an unchanged model no longer causes
  a replacement conflict or rewrites the configuration.
- **Cached prices follow their model and account.** Published prices carry their
  source and revision into usage records. Missing prices stay unknown, and
  pooled credentials do not expose one account's rates as another's.

## Under the hood

- Provider discovery uses bounded, cancellable requests, conditional refreshes,
  private atomic cache files and retry backoff. Inactive keychain accounts are
  not unlocked for background discovery.
- Agent Runtime remains pinned to v0.6.2 (`e38809e`).
