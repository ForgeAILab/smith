# Smith v0.7.1

Smith 0.7.1 fixes Gemini sessions that stopped after a response both
searched the web and called tools.

## Upgrade notes

- **Session formats are unchanged.** Sessions written by 0.7.0 resume in
  0.7.1. Runtime events in stream-json stay at event schema 16, and the
  result envelope stays at schema 3.
- **A session that already failed this way cannot continue on Gemini.** Its
  saved history is missing the search steps, and Gemini rejects the
  history. Resume it with another profile (for example
  `smith --resume <id> --profile sol`); other providers continue it normally.

## Fixes

- **Gemini continues after a search and tool calls in one response.** When
  `gemini-4-argon` ran Google Search and called tools in the same response,
  that response had no thinking step, and its signatures were on the search
  steps. Smith dropped those steps, and the next request failed with
  `Config: Gemini signed continuation is incomplete or out of order`. The
  search steps are now kept and sent back unchanged, in the order Gemini
  emitted them. Gemini also rejects them if a search result comes before the
  call it followed. Hosted-search events, the transcript, and errors still
  never show the opaque search data. Other providers ignore these steps.
  Checked live on `google/gemini-4-argon`: a response with a search and a
  tool call continued through three more requests.

## Known limits

- Each later Gemini request resends every search step, about 9k tokens per
  search in the live check (mostly Gemini's signature). Google requires
  this. After the first resend, Gemini usually serves it from its cache.
- Gemini's prompt cache is automatic and best effort. Smith's Gemini
  requests were checked to be exact prefix extensions of the previous
  request across 14 consecutive requests, and Gemini still read nothing from
  cache on about one in six. Gemini 4 Argon has no explicit caching, so a
  session rate around 60-75% is expected.

## Under the hood

- Agent Runtime moves to v0.6.1 (`3f8b56b`). It brings the Gemini fix
  (agent-runtime PR #41) and the session journal work, which Smith does not
  use yet. v0.6.1 also boxes the runtime's session startup (PR #43). Without
  that, debug builds of Smith overflowed their stack when a tool call
  started a sub-agent.
